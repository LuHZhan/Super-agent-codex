# 开发文档的阅读需求

## 已确认的要求

2026-11-02：用户认为 Superpowers 的文档产物过重，人类阅读困难。开发工作流需要同时提供面向人类和面向 AI 的不同文档，两者的技术结构与含义保持一致，人类版本应更容易阅读。

这一要求针对的是本项目使用的开发工作流；尚不意味着 Codex Super-agent 产品本身需要实现文档生成能力。

用户进一步确认：人类版是设计变更的入口，也可以通过聊天提出调整；AI 负责识别受影响的技术条目并同步，遇到歧义时提出具体问题。同步不应在 AI 文档中引入未确认的产品决策。

## 已采用的工作流

2026-11-02：用户确认采用 grill-with-docs 澄清需求、OpenSpec 管理规格与变更，并为模块级变更提供人类与 AI 双文档视图。完整执行约定见根目录 [AGENT.md](../AGENT.md)，本文件保留需求来源，不独立维护第二套流程。

- 人类以自定义的 `overview.md` 阅读和修改设计；技术视图由 `proposal.md`、capability spec、`design.md`、`tasks.md` 按职责组成。
- 两种视图使用一致的术语和稳定标识。人类视图可省略操作细节，但必须保留组件边界、关键流程以及行为、权限、成本、可靠性方面的重要决定。
- AI 同步受影响文档；发现歧义或冲突时标记具体条目，澄清后再推进依赖该决定的实现，不静默选边。
- 通过内容核对检查语义一致性；OpenSpec 的结构校验不能替代语义检查或实现验证。
- 共享词汇表，按需记录 ADR，默认不生成重复报告或机械拆分的执行计划。

本次确认的是工作约定，不表示 OpenSpec CLI 已安装、规格目录已初始化或产品实现已获授权。
